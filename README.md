## نصب روی یک کامپیوتر تازه (ویندوز)

1. از گیت‌هاب ZIP پروژه را بگیرید (Code ← Download ZIP) و در یک پوشه باز کنید، مثلاً `Documents\orchestra-ai-main`.
2. روی **`setup.bat`** دو بار کلیک کنید. خودش این کارها را می‌کند:
   - اگر پایتون نیست، نصبش می‌کند؛ محیط برنامه و کتابخانه‌ها را می‌سازد؛ مرورگر لازم برای اسلاید را پیدا می‌کند؛
   - **تنظیمات را می‌پرسد**: کلید Gemini (همان‌جا امتحانش می‌کند)، توکن ربات تلگرام؛
   - **شناسهٔ کانال تست را خودش پیدا می‌کند**: ربات را در کانال ادمین کنید و یک پیام در کانال بفرستید؛
   - **شناسهٔ شما را برای ربات کنترل پیدا می‌کند**: از تلگرام خودتان به ربات `/start` بفرستید؛
   - پایگاه‌داده را می‌سازد و (اگر بخواهید) ربات کنترل را با روشن شدن ویندوز خودکار روشن می‌کند.
3. برای تلگرام و Gemini، VPN باید روشن باشد.

دوباره اجرا کردن `setup.bat` بی‌خطر است: هر چیزی را که از قبل هست با Enter نگه می‌دارد. هیچ رمزی روی صفحه نمایش داده نمی‌شود.

| کار | فایل |
| --- | --- |
| ساخت گزارش امروز (درخواست در `request.txt`) | `run_ask.bat` |
| دیدن محتوای آماده، تأیید و انتشار | `approve_publish.bat` |
| ربات کنترل روی گوشی + زمان‌بندی روزانه | `run_service.bat` |
| برداشتن روشن شدن خودکار | `uninstall_autostart.bat` |

## راه‌اندازی دستی (برای توسعه)

1. **Python 3.12** را از python.org نصب کنید (گزینهٔ «Add python.exe to PATH» را بزنید).
2. **PostgreSQL 16** را از postgresql.org نصب کنید. رمز کاربر `postgres` را یادداشت کنید.
3. در **SQL Shell (psql)** پایگاه‌داده بسازید:

   ```sql
   CREATE USER orchestra WITH PASSWORD 'orchestra';
   CREATE DATABASE orchestra OWNER orchestra;
   CREATE DATABASE orchestra_dbos OWNER orchestra;
   CREATE DATABASE orchestra_test OWNER orchestra;
   ```

4. در PowerShell، داخل پوشهٔ پروژه:

   ```powershell
   py -3.12 -m venv .venv
   .venv\Scripts\Activate.ps1
   pip install -e ".[dev]"
   playwright install chromium
   copy .env.example .env
   ```

   اگر PowerShell اجرای اسکریپت را نپذیرفت، یک بار بزنید: `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`

5. **اجرای تست‌ها:**

   ```powershell
   pytest
   ```

   تست‌ها روی SQLite و Postgres اجرا می‌شوند. اگر Postgres در دسترس نباشد، فقط SQLite اجرا می‌شود.

## دادن کار به تیم (Manager)

```powershell
python -m orchestra.cli ask "گزارش پایان بازار امروز را برای همهٔ کانال‌ها آماده کن"
python -m orchestra.cli ask "گزارش بازار امروز با تحلیل تکنیکال شاخص کل برای اینستاگرام"
python -m orchestra.cli show <RUN_ID>     # متن هر کانال، منبع هر عدد، و اسلایدها در پوشهٔ previews
python -m orchestra.cli approve <RUN_ID>
```

مدیر درخواست را به یکی از کارهای `registry/templates` تبدیل می‌کند، یا سؤال می‌پرسد، یا (برای توصیهٔ خرید و فروش
یا موضوع ممنوع سازمان) رد می‌کند. برای تحلیل تکنیکال و بنیادی، فعلاً داده را با فایل وارد کنید:

```powershell
python -m orchestra.cli import-prices --subject "شاخص کل" index.csv     # ستون‌ها: تاریخ، اولین، بیشترین، کمترین، پایانی، حجم
python -m orchestra.cli import-statements folad.yaml                    # صورت‌های مالی؛ نمونه در tests/test_specialists.py
```

**اینستاگرام:** حساب Business یا Creator متصل به صفحهٔ فیسبوک، توکن بلندمدت با مجوز `instagram_content_publish`
(در `.env` با نامی که در `destinations.yaml` نوشته‌اید)، و یک پوشه که وب‌سرور شما آن را عمومی منتشر می‌کند
(`ORCHESTRA_PUBLIC_ASSET_DIR` و `ORCHESTRA_PUBLIC_ASSET_URL`)، چون اینستاگرام تصویر را از آدرس عمومی برمی‌دارد.
برای ساخت اسلاید یک بار بزنید: `playwright install chromium`.

**قاعدهٔ سهم تکی:** طبق پروفایل V3، پویان دربارهٔ یک نماد مشخص پست نمی‌گذارد؛ برای همین تحلیل بنیادی یک نماد و
گزارش یک نماد رد می‌شود و تحلیل تکنیکال فقط برای شاخص‌ها مجاز است. برای فعال کردن، در `orgs/pouyan/brand.yaml`
بنویسید `single_stock_content: true`.

## ربات کنترل: کار با تیم از روی گوشی

با این ربات از گوشی درخواست می‌دهید، متن هر کانال و اسلایدهای اینستاگرام را می‌بینید و با یک دکمه تأیید یا رد می‌کنید. تا وقتی برنامه روی کامپیوتر روشن است، ربات جواب می‌دهد.

1. یک ربات بسازید: در **بله** یا **تلگرام** به `@BotFather` پیام بدهید و توکن بگیرید. (بله بدون VPN کار می‌کند.)
2. در `.env` بنویسید:
   ```
   ORCHESTRA_CONTROL_PLATFORM=bale
   ORCHESTRA_CONTROL_BOT_TOKEN=توکن ربات
   ```
3. روی `run_service.bat` دو بار کلیک کنید و به ربات یک پیام بدهید؛ ربات **شناسهٔ عددی** شما را می‌گوید.
4. آن عدد را در `.env` بنویسید (`ORCHESTRA_CONTROL_CHAT_IDS=عدد`؛ چند نفر با کاما) و `run_service.bat` را دوباره اجرا کنید.

از این به بعد: درخواست را ساده برای ربات بنویسید. زیر هر محتوای آماده سه دکمه هست: **تأیید و انتشار**، **اصلاح** (بنویسید چه چیزی عوض شود؛ تیم از همان داده‌ها نسخهٔ جدید می‌سازد، تا ۳ بار) و **رد**. دستورها: `/status`، `/jobs`، `/pause`، `/resume`، `/sent شماره`، `/retry شماره`. به‌جای دکمه می‌توانید بنویسید «تأیید ۱۲»، «اصلاح ۱۲ توضیح» یا «رد ۱۲ دلیل». از روی کامپیوتر: `python -m orchestra.cli revise RUN_ID --note "..."`.

- فقط شناسه‌های `ORCHESTRA_CONTROL_CHAT_IDS` اطاعت می‌شوند؛ بقیه نادیده گرفته می‌شوند.
- اگر نسخهٔ جدید ساخته نشود (مثلاً کنترل کیفیت آن را نپذیرد)، دلیلش گفته می‌شود و نسخهٔ قبلی همچنان منتظر تصمیم می‌ماند.
- تأیید به همان محتوایی وصل است که دیده‌اید؛ دکمهٔ محتوای قدیمی کاری نمی‌کند و دو بار زدن دکمه چیزی را دو بار نمی‌فرستد.
- زمان‌بندی روزانه در `orgs/pouyan/schedule.yaml` است (پیش‌فرض: گزارش پایان بازار، شنبه تا چهارشنبه ۱۲:۴۵). کار زمان‌بندی‌شده هم فقط آماده و برای تأیید فرستاده می‌شود.

## تقویم محتوا (کارمند بازاریابی)

کارمند بازاریابی برنامهٔ انتشار کانال را برای یک دوره (پیش‌فرض: یک هفته از شنبه) می‌چیند: کدام محور و موضوع، چه روز و
ساعتی، از چه زاویه‌ای. قواعد در `orgs/pouyan/marketing.yaml` است: روزها و ساعت‌های انتشار، حداکثر پست در روز و فاصلهٔ
پست‌ها (با احتساب گزارش ثابت روزانه)، و تعداد پست هر محور. کد برنامه را با این قواعد می‌سنجد؛ برنامهٔ نادرست به شما نشان داده نمی‌شود.

- در ربات: `/plan` (برنامهٔ هفتهٔ بعد) یا `/plan فردا`؛ برنامه با دکمه‌های **تأیید برنامه**، **اصلاح** (بنویسید چه عوض شود) و **رد** می‌آید.
  `/plans` برنامهٔ تأییدشده و وضعیت هر پست را نشان می‌دهد. پنجشنبه‌ها ساعت ۱۰ برنامهٔ هفتهٔ بعد خودکار پیشنهاد می‌شود (`auto_propose`).
- پس از تأیید برنامه، هر پست ۹۰ دقیقه پیش از ساعتش ساخته می‌شود و **جدا** برای تأیید شما می‌آید؛ پس از تأیید، سر ساعتش منتشر می‌شود.
  تأیید برنامه به‌تنهایی چیزی منتشر نمی‌کند.
- واقعیت‌های پست‌های موضوعی فقط از `orgs/pouyan/knowledge.yaml` می‌آیند. عددها فقط در بخش `facts` آن فایل‌اند و نویسنده
  آن‌ها را تایپ نمی‌کند. اطلاعات تازه (مثلاً کارمزد یا مدت ارزیابی) را همان‌جا اضافه کنید.
- از روی کامپیوتر: `python -m orchestra.cli plan` و `python -m orchestra.cli plan-approve شماره` (پست‌ها وقتی `run_service.bat` روشن است ساخته می‌شوند).

## خلاصهٔ خبرها (کارمند پژوهش)

کارمند پژوهش خبرهای چند ساعت اخیر را از منبع‌های `orgs/pouyan/research.yaml` (فید سایت‌ها و کانال‌های عمومی تلگرام)
جمع می‌کند، خبرهای دربارهٔ صندوق‌ها را با کد کنار می‌گذارد و مدل از میان بقیه مهم‌ترین‌ها را برای مخاطب انتخاب می‌کند.
نویسنده فقط از متن همان خبرها می‌نویسد. **هر عدد خبر** (مثلاً «۸۰ دلار» یا «۲٫۵ درصد») با جمله و منبعش ثبت می‌شود و
نویسنده فقط با توکن به آن ارجاع می‌دهد؛ عددی که خودش تایپ کند پست را متوقف می‌کند. نشانی و هش هر خبر در بستهٔ انتشار هست.

- درخواست: «مهم‌ترین خبرهای امروز را که روی بازار اثر دارند خلاصه کن» (در ربات یا `run_ask.bat`).
- خلاصهٔ خبر جزو تقویم کارمند بازاریابی است (`marketing.yaml`، محور `news`): هر روز انتشار یکی، بین ۹ و ۱۰:۳۰، و مثل
  بقیهٔ پست‌های برنامه جدا برای تأیید شما می‌آید. اگر خبر مهمی نباشد، آن روز پستی ساخته نمی‌شود و به شما گفته می‌شود.
- منبعی که جواب ندهد فقط گزارش می‌شود؛ منبع‌های `foreign: true` (تلگرام، رسانه‌های خارجی) از مسیر VPN گرفته می‌شوند.
  اگر وصل نشدند، `capture_sources.bat` را با VPN روشن اجرا کنید: پورت محلی VPN را پیدا می‌کند و خطی مثل
  `ORCHESTRA_FOREIGN_PROXY=socks5://127.0.0.1:10808` پیشنهاد می‌دهد که باید در `.env` بنویسید.
- `capture_sources.bat` حالا منبع‌های خبری را هم می‌گیرد؛ zip آن را بفرستید تا parserها روی پاسخ واقعی آزموده شوند.

## حافظهٔ تیم (درس از بازخوردهای شما)

وقتی محتوایی را با توضیح اصلاح یا با دلیل رد می‌کنید، یا برنامهٔ محتوا را با یادداشت پس می‌فرستید، ربات می‌پرسد:
«این را قاعدهٔ همیشگی کنم؟» با «بله، همیشه»، همان جملهٔ شما از این به بعد در دستور نویسنده و ویراستار (یا برنامه‌ریز تقویم)
می‌آید؛ با «فقط همین بار» چیزی نگه داشته نمی‌شود. `/lessons` فهرست قاعده‌ها را با دکمهٔ برداشتن نشان می‌دهد و
`/lesson متن` مستقیم قاعده‌ای اضافه می‌کند. قاعده‌ها هیچ‌وقت بر قواعد اصلی (عدد فقط از داده، عبارت و موضوع ممنوع، لینک)
مقدم نیستند و متنی که خودش عبارت ممنوع یا لینک داشته باشد قاعده نمی‌شود. هر بستهٔ انتشار نشان می‌دهد با کدام مجموعهٔ
قاعده‌ها نوشته شده است.

## سرنخ‌های تامین مالی (CRM)

یک **ربات پذیرش** جدا (نه ربات کنترل) با متقاضیان حرف می‌زند: متن رضایت را نشان می‌دهد، سؤال‌های `orgs/pouyan/crm.yaml` را
به‌ترتیب می‌پرسد (شرکت، نام، تلفن، مبلغ، زمینهٔ فعالیت)، خلاصه را برای تأیید نشان می‌دهد و سرنخ را ثبت می‌کند.

1. در @BotFather (بله یا تلگرام؛ همان که در `crm.yaml` نوشته‌اید) یک ربات تازه بسازید و توکنش را در `.env` بنویسید:
   `ORCHESTRA_INTAKE_BOT_TOKEN=...`. با `run_service.bat` همراه ربات کنترل روشن می‌شود.
2. پیوندش را زیر پست‌ها یا در `footer_links` فایل `brand.yaml` بگذارید، مثلاً `https://ble.ir/نام_ربات?start=channel`.
   هر چیزی بعد از `?start=` منشأ سرنخ است و در گزارش می‌آید.

هر سرنخ تازه با دکمه‌های مرحله (تماس گرفته شد، در ارزیابی، ثبت در فرابورس، تامین شد، منتفی) در ربات کنترل می‌آید.
دستورها: `/leads`، `/lead شماره` (جزئیات و سابقه)، `/note شماره متن`. سرنخی که ۲۴ ساعت تماس نگرفته باشد یک بار یادآوری می‌شود.
از روی کامپیوتر: `python -m orchestra.cli leads` و `python -m orchestra.cli leads 12 --stage contacted`.
اطلاعات سرنخ‌ها فقط در پایگاه‌دادهٔ همین کامپیوتر و ربات کنترل است؛ هرگز به مدل زبانی داده نمی‌شود و در دفتر ممیزی فقط
شمارهٔ سرنخ و مرحله‌اش ثبت می‌شود. از هر نفر حداکثر ۳ ثبت در ۲۴ ساعت پذیرفته می‌شود و پاسخ دوباره همان سرنخ باز را به‌روز می‌کند.

## گزارش عملکرد (کارمند گزارش‌گیری)

هر جمعه ساعت ۲۰ گزارش هفت روز گذشته در ربات کنترل می‌آید (`orgs/pouyan/reporting.yaml`). هر وقت خواستید: `/report`،
`/report امروز` یا `/report 30`. از روی کامپیوتر: `python -m orchestra.cli report --days 7`.

گزارش همه‌چیز را از سوابق خود سیستم می‌شمارد، بدون مدل زبانی و بدون تخمین: درخواست‌ها و منشأشان، محتوای آماده، تأیید و رد
(با دلیل‌های شما) و اصلاح‌ها، زمان آماده‌سازی و زمان تصمیم، ارسال‌ها به تفکیک کانال، پایبندی به برنامهٔ محتوا، ایرادهای
کنترل کیفیت، و تعداد و هزینهٔ تماس‌های مدل. آخرش «نیاز به توجه» می‌آید: ارسال نامعلوم، پست جامانده، محتوای منتظر، منبع داده‌ای
که نیامد. گزارش فقط برای شماست و منتشر نمی‌شود. آمار مخاطب (بازدید و واکنش) در آن نیست، چون API ربات آن را نمی‌دهد.

## اجرای «تحلیل پایان بازار» (نسخهٔ سادهٔ فقط متن)

پیش از اجرا در `.env` کلید مدل زبانی (`ORCHESTRA_LLM_API_KEY` و `ORCHESTRA_LLM_MODEL`) و در `orgs/pouyan/destinations.yaml` نام کانال‌های **آزمایشی** را بنویسید.

```powershell
python -m orchestra.cli init                  # یک بار: ساخت جدول‌ها و ثبت مقصدها
python -m orchestra.cli run                   # داده می‌گیرد، می‌نویسد، بررسی می‌کند و منتظر تأیید می‌ماند
python -m orchestra.cli show <RUN_ID>         # متن دقیق هر کانال و منبع هر عدد
python -m orchestra.cli approve <RUN_ID>      # یا: reject <RUN_ID> --reason "..."
python -m orchestra.cli publish               # ارسال کارهای تأییدشده
python -m orchestra.cli jobs                  # وضعیت ارسال‌ها
```

اگر ارسالی «نامعلوم» شد، کانال را ببینید: اگر پست هست `confirm-sent <JOB_ID>`، اگر نیست `retry <JOB_ID>`. توقف اضطراری: `pause`.

## گرفتن نمونهٔ واقعی منابع داده

```powershell
python scripts/capture_sources.py
```

پوشهٔ `captures` ساخته می‌شود؛ آن را zip کنید و بفرستید تا parser هر منبع از دادهٔ واقعی نوشته شود.

## اصول

- هیچ پستی بدون تأیید معتبر برای hash دقیق بسته و مقصد منتشر نمی‌شود.
- ارسالی که نتیجه‌اش معلوم نیست، خودکار دوباره فرستاده نمی‌شود؛ انسان تصمیم می‌گیرد.
- هیچ عددی را مدل نمی‌نویسد؛ مدل فقط توکن می‌گذارد و کد عدد را از دادهٔ ذخیره‌شده با منبعش جایگزین می‌کند.
- توکن‌ها فقط در `.env` هستند؛ پایگاه‌داده فقط نام متغیر را نگه می‌دارد.
