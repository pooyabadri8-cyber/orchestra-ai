## راه‌اندازی روی ویندوز

1. **Python 3.12** را از python.org نصب کنید (گزینهٔ «Add python.exe to PATH» را بزنید).
2. **PostgreSQL 16** را از postgresql.org نصب کنید. رمز کاربر `postgres` را یادداشت کنید.
3. در **SQL Shell (psql)** پایگاه‌داده بسازید:

   ```sql
   CREATE USER orchestra WITH PASSWORD 'orchestra';
   CREATE DATABASE orchestra OWNER orchestra;
   CREATE DATABASE orchestra_dbos OWNER orchestra;
   CREATE DATABASE orchestra_test OWNER orchestra;
   ```

4. در PowerShell، داخل پوشهٔ پروژه:

   ```powershell
   py -3.12 -m venv .venv
   .venv\Scripts\Activate.ps1
   pip install -e ".[dev]"
   playwright install chromium
   copy .env.example .env
   ```

   اگر PowerShell اجرای اسکریپت را نپذیرفت، یک بار بزنید: `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`

5. **اجرای تست‌ها:**

   ```powershell
   pytest
   ```

   تست‌ها روی SQLite و Postgres اجرا می‌شوند. اگر Postgres در دسترس نباشد، فقط SQLite اجرا می‌شود.

## دادن کار به تیم (Manager)

```powershell
python -m orchestra.cli ask "گزارش پایان بازار امروز را برای همهٔ کانال‌ها آماده کن"
python -m orchestra.cli ask "گزارش بازار امروز با تحلیل تکنیکال شاخص کل برای اینستاگرام"
python -m orchestra.cli show <RUN_ID>     # متن هر کانال، منبع هر عدد، و اسلایدها در پوشهٔ previews
python -m orchestra.cli approve <RUN_ID>
```

مدیر درخواست را به یکی از کارهای `registry/templates` تبدیل می‌کند، یا سؤال می‌پرسد، یا (برای توصیهٔ خرید و فروش
یا موضوع ممنوع سازمان) رد می‌کند. برای تحلیل تکنیکال و بنیادی، فعلاً داده را با فایل وارد کنید:

```powershell
python -m orchestra.cli import-prices --subject "شاخص کل" index.csv     # ستون‌ها: تاریخ، اولین، بیشترین، کمترین، پایانی، حجم
python -m orchestra.cli import-statements folad.yaml                    # صورت‌های مالی؛ نمونه در tests/test_specialists.py
```

**اینستاگرام:** حساب Business یا Creator متصل به صفحهٔ فیسبوک، توکن بلندمدت با مجوز `instagram_content_publish`
(در `.env` با نامی که در `destinations.yaml` نوشته‌اید)، و یک پوشه که وب‌سرور شما آن را عمومی منتشر می‌کند
(`ORCHESTRA_PUBLIC_ASSET_DIR` و `ORCHESTRA_PUBLIC_ASSET_URL`)، چون اینستاگرام تصویر را از آدرس عمومی برمی‌دارد.
برای ساخت اسلاید یک بار بزنید: `playwright install chromium`.

**قاعدهٔ سهم تکی:** طبق پروفایل V3، پویان دربارهٔ یک نماد مشخص پست نمی‌گذارد؛ برای همین تحلیل بنیادی یک نماد و
گزارش یک نماد رد می‌شود و تحلیل تکنیکال فقط برای شاخص‌ها مجاز است. برای فعال کردن، در `orgs/pouyan/brand.yaml`
بنویسید `single_stock_content: true`.

## ربات کنترل: کار با تیم از روی گوشی

با این ربات از گوشی درخواست می‌دهید، متن هر کانال و اسلایدهای اینستاگرام را می‌بینید و با یک دکمه تأیید یا رد می‌کنید. تا وقتی برنامه روی کامپیوتر روشن است، ربات جواب می‌دهد.

1. یک ربات بسازید: در **بله** یا **تلگرام** به `@BotFather` پیام بدهید و توکن بگیرید. (بله بدون VPN کار می‌کند.)
2. در `.env` بنویسید:
   ```
   ORCHESTRA_CONTROL_PLATFORM=bale
   ORCHESTRA_CONTROL_BOT_TOKEN=توکن ربات
   ```
3. روی `run_service.bat` دو بار کلیک کنید و به ربات یک پیام بدهید؛ ربات **شناسهٔ عددی** شما را می‌گوید.
4. آن عدد را در `.env` بنویسید (`ORCHESTRA_CONTROL_CHAT_IDS=عدد`؛ چند نفر با کاما) و `run_service.bat` را دوباره اجرا کنید.

از این به بعد: درخواست را ساده برای ربات بنویسید. زیر هر محتوای آماده سه دکمه هست: **تأیید و انتشار**، **اصلاح** (بنویسید چه چیزی عوض شود؛ تیم از همان داده‌ها نسخهٔ جدید می‌سازد، تا ۳ بار) و **رد**. دستورها: `/status`، `/jobs`، `/pause`، `/resume`، `/sent شماره`، `/retry شماره`. به‌جای دکمه می‌توانید بنویسید «تأیید ۱۲»، «اصلاح ۱۲ توضیح» یا «رد ۱۲ دلیل». از روی کامپیوتر: `python -m orchestra.cli revise RUN_ID --note "..."`.

- فقط شناسه‌های `ORCHESTRA_CONTROL_CHAT_IDS` اطاعت می‌شوند؛ بقیه نادیده گرفته می‌شوند.
- اگر نسخهٔ جدید ساخته نشود (مثلاً کنترل کیفیت آن را نپذیرد)، دلیلش گفته می‌شود و نسخهٔ قبلی همچنان منتظر تصمیم می‌ماند.
- تأیید به همان محتوایی وصل است که دیده‌اید؛ دکمهٔ محتوای قدیمی کاری نمی‌کند و دو بار زدن دکمه چیزی را دو بار نمی‌فرستد.
- زمان‌بندی روزانه در `orgs/pouyan/schedule.yaml` است (پیش‌فرض: گزارش پایان بازار، شنبه تا چهارشنبه ۱۲:۴۵). کار زمان‌بندی‌شده هم فقط آماده و برای تأیید فرستاده می‌شود.

## اجرای «تحلیل پایان بازار» (نسخهٔ سادهٔ فقط متن)

پیش از اجرا در `.env` کلید مدل زبانی (`ORCHESTRA_LLM_API_KEY` و `ORCHESTRA_LLM_MODEL`) و در `orgs/pouyan/destinations.yaml` نام کانال‌های **آزمایشی** را بنویسید.

```powershell
python -m orchestra.cli init                  # یک بار: ساخت جدول‌ها و ثبت مقصدها
python -m orchestra.cli run                   # داده می‌گیرد، می‌نویسد، بررسی می‌کند و منتظر تأیید می‌ماند
python -m orchestra.cli show <RUN_ID>         # متن دقیق هر کانال و منبع هر عدد
python -m orchestra.cli approve <RUN_ID>      # یا: reject <RUN_ID> --reason "..."
python -m orchestra.cli publish               # ارسال کارهای تأییدشده
python -m orchestra.cli jobs                  # وضعیت ارسال‌ها
```

اگر ارسالی «نامعلوم» شد، کانال را ببینید: اگر پست هست `confirm-sent <JOB_ID>`، اگر نیست `retry <JOB_ID>`. توقف اضطراری: `pause`.

## گرفتن نمونهٔ واقعی منابع داده

```powershell
python scripts/capture_sources.py
```

پوشهٔ `captures` ساخته می‌شود؛ آن را zip کنید و بفرستید تا parser هر منبع از دادهٔ واقعی نوشته شود.

## اصول

- هیچ پستی بدون تأیید معتبر برای hash دقیق بسته و مقصد منتشر نمی‌شود.
- ارسالی که نتیجه‌اش معلوم نیست، خودکار دوباره فرستاده نمی‌شود؛ انسان تصمیم می‌گیرد.
- هیچ عددی را مدل نمی‌نویسد؛ مدل فقط توکن می‌گذارد و کد عدد را از دادهٔ ذخیره‌شده با منبعش جایگزین می‌کند.
- توکن‌ها فقط در `.env` هستند؛ پایگاه‌داده فقط نام متغیر را نگه می‌دارد.
